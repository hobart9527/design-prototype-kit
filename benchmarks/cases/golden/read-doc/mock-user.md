# Mock user: Public Document Reader

## Held Facts
- 读者是市民、律师助理和规划从业者，不是内部员工。
- 正文是条例征求意见稿，条款分章、条、款三级。
- 需要按条款号互相引用，引用必须精确到款。
- 需要对照现行版本，看出新增、删除和修改。
- 桌面长时阅读为主，手机在地铁上读一段。

## Decision Answers
- 明暗|深浅|主题|配色: 主要在地铁和办公室读，白天多，浅色为主，要有纸张的感觉，不要暗色酷炫风。
- 条款号|编号|引用|复制: 条款号要能一键复制，编号要等宽，滚动时不能跳动。
- 键盘|快捷键|跳转: 桌面端希望键盘能跳到下一条，别只能用鼠标。
- 差异|对比|修订|标注: 红绿对比太刺眼，而且分不清是新增还是删除，要更克制的方式。
- 手机|移动端|响应式: 手机上只要能连续读和定位条款，不要求在手机上写意见。
- 字体|排版|行宽: 正文要耐读，行宽别太宽，字号别太小。

## Direction Choice
- 方向|direction|世界|world|候选|哪一版: 选 A——法规书那一版。我要的是能一直读下去、条款号随时找得到的感觉，不要做成资讯流或者仪表盘。B 版那种报纸专栏也行，但如果两边差不多，就选更像正式文本的。
- 对比|差异|两个方向|哪边更好: 差别要能一眼看出来，不是换个颜色。如果只是配色不同，那等于没给我选。
- 重新|再来|换一版|不满意: 两个都不像正式文本，就重做；重做前先告诉我你想换成哪个世界。

## Fallback
没有更强偏好，按你的专业判断做，但不要发明我们没提到的系统能力。
