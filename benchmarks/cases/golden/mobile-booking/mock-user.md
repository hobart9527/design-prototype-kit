# Mock user: Mobile Booking

## Held Facts
- 用户在手机上单手完成：选服务、选技师、挑时段、付定金、进日程。
- 最大的流失点是时段已被占用后要退回重挑。
- 用户年龄跨度大，操作能力差异大。

## Decision Answers
- 定金|金额|比例: 定金按服务价格的 20%，页面上要写清楚可退规则入口。
- 时段冲突|被占用|约满: 冲突时必须就地给替代时段，不要让人退回上一页重选。
- 支付|支付方式|渠道: 只做一种支付方式，这一版不接多种钱包。
- 日程|日历|写入: 预约成功后写进手机日历只是提示，不要求真正打通系统日历。
- 会员|优惠|促销: 不做会员和优惠券，第一版只做预约本身。
- 技师|排行|评价: 技师列表不要做评分排行，用户主要看可约时间。
- 触控|字号|可访问性: 按钮要大，手指不灵活的人也能点到。

## Fallback
没有更强偏好，按专业判断做，不要发明会员、优惠或社交能力。
