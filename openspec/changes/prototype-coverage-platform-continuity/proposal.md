## Why

The design engine already defines Double Diamond, Nine Pillars, Five Axes, method routing and a Spec-led five-stage lifecycle. Its execution seams do not yet reliably distinguish selected prototype coverage, target-platform adaptation, actual evidence environments and conditional whole-product rollout. Users should choose concrete page combinations from an informed Surface Map rather than write scope-control prompts.

## What Changes

- Add a Stage 3 coverage decision using the current Surface Map and probe findings; preserve explicit prior scope and lightweight exploration routes.
- Add authored Platform Context and Platform Adaptation Contract sections to existing authorities, separating target environment, prototype medium and verification environment.
- Project selected scope and applicable platform constraints into Builder envelopes without replacing product meaning or method outcomes with defaults.
- Continue whole-product rollout only for explicit `coverage=full-product`; use the same batch and completion logic for selected scopes.
- Derive portal coverage and completion from declared scope, delivered artifacts and revision-bound evidence; keep product navigation distinct from review metadata.
- Repair directly related navigation checks, evidence false passes and handoff integrity seams. Preserve existing design authority and approval boundaries.
- Add focused mechanism tests and an opt-in real-session regression specimen; no paid sessions are authorized by this specification work.

## Capabilities

### New Capabilities

- `design-engine/coverage-platform-continuity`: Scope selection, platform-aware execution/evidence, conditional rollout, and continuity obligations across the existing design authority chain.

### Modified Capabilities

None. This capability adds concrete obligations to the existing lifecycle and verification contracts; it does not replace ENG, HAR or BENCH requirements. Existing specification/implementation mismatches outside the owned seams remain outside this change.

## Impact

- Skill entry and core workflow; governance references; product, foundation, Surface Map and slice specification templates.
- Contract materialization, envelope assembly, execution boundary, quality verification, capture, review portal and handoff.
- Existing Builder and Critic contracts, benchmark judges and focused pytest tests.
- No new Skill, dependency, workflow database, native app toolchain or mandatory full-product ceremony.
- Source documents remain authoritative; generated JSON and portal views are derived. Legacy artifacts require explicit scope/platform normalization before new completion claims; no bulk rewrite or inferred approval.

This change currently delivers proposal, behavioral specifications, design decisions and executable implementation tasks only. Do not edit product implementation, approve a delivery, commit, or run paid benchmarks during authoring. Preserve unrelated working-tree changes. Implementation is a later lifecycle.
