## Why

The Skill currently conflates artifact completeness with experience quality. Its generic helpers embed a GPU use case, its single-pass Builder instruction conflicts with evidence-led revision, and generated records can assert success before verification. Earlier attempts to impose fixed scaffolds would replace one bias with another rather than repair the design process.

## What Changes

- **BREAKING** Replace mandatory sequential five-stage execution and fixed motion recipes with intent-sensitive exploration, new-surface, local-refinement, and formal-handoff behavior.
- Preserve task reasoning, existing assets, and uncertainty in Builder inputs; remove compulsory scaffold injection and globally fixed tool-turn budgets.
- Remove domain-specific materialization and pre-filled observed results; retain authoritative project decisions instead of manufacturing them.
- Compile explicit project tokens without silent aesthetic defaults or automatic frozen status.
- Separate static checks, browser behavior, visual review, and human approval. Restore render/read/repair/reverify behavior and honest partial results.
- Formal freezing retains reference integrity and safety checks; it does not confer design approval.
- Validate generality with focused cross-domain and negative regression cases, without rebuilding the GPU prototype.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `design-engine/lifecycle`: Intent-sensitive routes, revisable exploration, project-owned visual decisions, and a bounded evidence-led Builder feedback loop.
- `design-engine/verification-harness`: Input-driven materialization and tokens, evidence-specific verification, truthful capture/portal/handoff results, and retained scope protections.

## Impact

Implementation targets are the source Skill under `skills/spec-prototype/`, its Builder/Critic definitions under `agents/`, and focused tests under `tests/`. Existing application prototypes, screenshots, Runtime storage, deployment copies, and unrelated working-tree changes are excluded. No mandatory layout library, global font/radius/density thresholds, new orchestration framework, or production UI migration is introduced. The authorized current Skill changes must be preserved as the execution baseline before candidate preparation; unrelated and prototype edits remain local.
